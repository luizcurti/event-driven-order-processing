# Project

Project name

event-driven-order-processing

Objective

Build a complete order processing system using an Event-Driven architecture on AWS.

This project is intended to be used as a professional portfolio to demonstrate expertise in:

- AWS Serverless
- Event-Driven Architecture
- Step Functions
- EventBridge
- API Gateway
- Lambda
- SQS
- DynamoDB
- CloudWatch
- WAF
- Terraform
- CI/CD
- Testing
- Observability

The system should represent an architecture similar to those used by companies such as Amazon, Mercado Livre, and iFood.

The goal is not only to deliver features, but also to demonstrate architecture, best practices, and code organization.

Quality requirements
Code in English (variable names, functions, classes, files, and comments).
TypeScript with strict mode enabled.
ESLint and Prettier configured.
Commits following Conventional Commits.
Public function documentation with JSDoc when it adds value.
Do not use `any` unless explicitly justified.
All dependencies should be the latest stable or LTS versions.

Portfolio differentiators

Add some capabilities commonly seen in real systems:

Idempotency in order creation (avoid duplicate orders).
Correlation ID propagated across API Gateway, EventBridge, Step Functions, and Lambdas.
Retry with exponential backoff for asynchronous calls.
Dead Letter Queue for unprocessed messages.
CloudWatch alarms for errors, SQS queue growth, and Step Functions failures.
Custom metrics (approved orders, rejected orders, average processing time).
Simple feature flags via environment variables to enable/disable fraud or inventory validation.
